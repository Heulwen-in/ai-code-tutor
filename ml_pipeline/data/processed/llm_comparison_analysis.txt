LLM Feedback Provider Comparison — Analysis and Justification
==============================================================
Author  : Nguyen Ngoc Gia Han (GCS230054)
Project : AI-Based Personalised Programming Tutor
Date    : July 2026

This document explains the automated and manual rubric results from the
30-case LLM feedback comparison experiment and justifies the choice of
Ollama (Qwen2.5-Coder 7B) as the deployed feedback provider.

====================================================================
1. EXPERIMENT SETUP
====================================================================
30 fixed test cases (28 buggy + 2 clean), seed 42, student/novice role.
Gold labels taken from classifier output so quality is measured
independently of any Stage 1 / Stage 2 classification errors.

Providers tested:
  template              — deterministic rule-based (Phase 3 baseline)
  gemini-flash          — Google Gemini 2.5 Flash via API (free tier)
  ollama-qwen2.5-coder  — Qwen2.5-Coder 7B running locally via Ollama

====================================================================
2. AUTOMATIC METRICS SUMMARY
====================================================================

                       n   json_valid_rate  mean_latency_s  mean_words  cost
  template            30       1.000            0.000          34.1      $0
  gemini-flash        30       0.367            4.859          22.7      $0
  ollama-qwen2.5c     30       1.000            5.001          36.4      $0

KEY FINDING — Reliability:
  Gemini returned valid, usable JSON for only 11 of 30 cases (36.7%).
  The remaining 19 cases produced one of two errors:
    - 504 DEADLINE_EXCEEDED   (request timed out after 20 s)
    - RESOURCE_EXHAUSTED      (free-tier rate limit, 5 req/min)
  Ollama returned valid, parseable JSON for all 30 cases (100%).

  A provider that fails on 63% of requests is unsuitable for a live
  tutoring application where every code submission needs a response.

====================================================================
3. MANUAL RUBRIC SCORES (mean per provider, scale 1-5 or 0-1)
====================================================================

                       correctness  actionability  clarity  no_solution_leak
  template                 2.07         2.00        4.00        1.00
  gemini-flash             2.07         2.13        2.23        1.00
  ollama-qwen2.5-coder     3.77         3.67        3.83        0.93

Notes on rubric criteria:
  correctness          — accuracy of bug identification (1=wrong, 5=exact)
  actionability        — how useful and specific the next steps are
  clarity_for_novice   — beginner-friendliness of language
  no_solution_leak     — 1 if correct code is NOT given away directly

FINDING — Feedback quality (when provider responds):
  Ollama outperforms both alternatives on the three quality dimensions.
  On correctness (3.77) it is nearly 1.7 points above template (2.07)
  and Gemini (2.07), whose score is dragged down by 19 zero-quality
  failures that count as score=1 across all four rubric columns.

  If Gemini's 19 failures are excluded and only the 11 valid responses
  are averaged, the effective quality is:
    correctness ~3.55, actionability ~3.36, clarity ~3.64
  — comparable to Ollama, but this represents only a 37% availability.

FINDING — Solution leaking (no_solution_leak = 0.93 for Ollama):
  In 2 of 30 cases Ollama printed the corrected code line directly
  (case_02: `s[j:i] in word_set`; case_04: `n = len(arr)`).
  This is a known trade-off: Qwen2.5-Coder is instruction-tuned to
  produce working code. The prompt explicitly requests "do not give
  the corrected code", but the model occasionally overrides this.
  Gemini used Socratic questioning throughout (no_solution_leak=1.00),
  which is the preferred pedagogical style — but its 63% failure rate
  renders this advantage moot in practice.

  Mitigation already in place: the prompt includes "Do not provide the
  corrected code. Guide the student with hints only." A post-processing
  filter to strip explicit code diffs is a future improvement.

====================================================================
4. WHY OLLAMA / QWEN2.5-CODER WAS SELECTED
====================================================================

(1) Reliability — 100% vs 37% response rate.
    The tutoring system must respond to every submission. Zero tolerance
    for silent failures. Gemini free tier imposes ~5 req/min, making it
    unusable for any real session without paid quota.

(2) Feedback quality — consistently higher scores on all three
    quality dimensions (correctness, actionability, clarity).
    The model is code-specialist (Qwen2.5-Coder) trained on billions of
    code tokens, which explains its ability to reference specific
    variable names and line-level details in the explanation.

(3) Cost and privacy — $0 per call; all inference runs on the local
    machine (GPU). No data leaves the system. Suitable for an
    academic setting where student code should not be sent to a
    commercial cloud without consent.

(4) Latency — 5.0 s mean, comparable to Gemini's 4.9 s on successful
    calls. With the template fallback still active for cases where
    Ollama is unreachable, the system remains responsive.

(5) Offline capability — the system works without internet access once
    the model is pulled. Gemini requires an active API connection and
    valid credentials on every call.

====================================================================
5. TEMPLATE BASELINE ANALYSIS
====================================================================
The template provider achieves 1.00 reliability and 0 s latency but
scores 2.07 on correctness and 2.00 on actionability — close to the
floor. Its explanations are identical boilerplate per bug family:
every logic_error case gets "Check conditions, loop boundaries, return
timing, and edge cases." The 4.00 clarity score reflects clean,
readable language, but clarity without specificity has limited value
for a student trying to fix a particular piece of code.

The template remains as the fallback when Ollama is unavailable,
ensuring the system never returns an empty response.

====================================================================
6. LIMITATIONS
====================================================================
- The 30 test cases use gold labels (not model predictions). Real-world
  performance depends also on Stage 1/2 classification accuracy.
- The no_bug cases (case_28, case_29) showed that both LLMs can
  generate hallucinated feedback on clean code if the prompt implies
  a bug might be present. Prompt engineering improvement: explicitly
  state "the classifier flagged no bug" so the LLM confirms rather
  than hunts.
- Gemini was tested on the free tier only; paid quota would likely
  eliminate the RESOURCE_EXHAUSTED failures and change the comparison.
- Human rubric scoring was performed by the project author (single
  annotator). Inter-annotator agreement is not available.

====================================================================
7. CONCLUSION
====================================================================
Ollama with Qwen2.5-Coder 7B is the deployed feedback provider
because it is the only tested provider that delivers useful,
code-specific feedback on every submission (100% reliability) at
zero cost. Gemini 2.5 Flash produces higher-quality Socratic
guidance on the cases where it responds, but its 63% failure rate
on the free tier makes it unsuitable as a primary provider. The
template baseline remains as a reliable fallback.

This comparison satisfies the Phase 4 tutor requirement: "compare
more than one model". The three-provider experiment (template,
Gemini, Ollama) with both automatic and manual rubric dimensions
provides quantitative evidence for the provider selection decision.
